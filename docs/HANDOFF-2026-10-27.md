## 8. 链路 A：资料库扫描与解析

### 8.1 扫描

1. 遍历 `libraryRoots` 下的 `.dem` 与平台 zip。
2. zip 先用 `zip-cache.json` 判断是否变化；未变化直接复用中央目录。
3. 变化的 zip 才 `new AdmZip`，并在 zip 之间 `setImmediate` 让出事件循环。
4. 扫描进度通过 `library:scan`（`phase: walk | zip | done`）推送。
5. UI 在扫描期间**保留现有卡片**，只在工具栏显示「检查压缩包 n/N」。

### 8.2 解析

- 入口：`library.parse(id)` / `library.parseAll()`。
- 队列串行，进度：`library:progress`（`stage` + `progress`）。
- 单条完成：`library:item` + `library:detail`。
- `parseAll` 会先标记 `parsing`，UI 立即出现旋转环（不要等第一条 progress）。
- `PARSER_VERSION` 在 `src/main/services/library.ts:164`，**改解析逻辑必须 +1**。

### 8.3 解析已知坑（来自 `AGENTS.md` + `progress.md`）

1. CS2 **首回合没有 `round_prestart`**，隐式回合要单独 close，否则手枪局整局丢失。
2. 换边判定用 `rounds.length + 1 > 12`（含隐式首回合）。
3. 玩家表权威来源是 `USER_INFO` 字符串表；5E 的实体 `_index` 有偏移，不可靠。
4. 回合胜负只看 `endTick` 之前的击杀；`tickrate` 从 demo 头读，不要硬编码 64。
5. 加时 / Rush 模式尚未适配（见第 12 章 R6）。

## 9. 链路 B：语音提取与转写

### 9.1 提取（csgove）

- 侧车：`userData\engines\csgove\`（`engines.ts` 负责下载/校验）。
- 模式：`-mode split-full`，每玩家全时长 WAV，时间轴对齐。
- **关键事实**：csgove 输出是**满幅 int32 PCM，语音在高 16 位**。`normalizeWav` 必须 `v >> 16`；取低 16 位会得到量化噪声（曾导致 whisper「广播幻觉」）。
- 只读 44 B 头判断格式，不要改回全量读。

### 9.2 VAD 与转写

- 优先复用「语音分割」段；没有才 `detectSpeech` VAD。
- 紧凑 WAV 段间插 `COMPACT_PAD_SEC = 0.3s` 静音，`mapCompactSegments` 同步计入。
- 本地：whisper-cli，`-l <lang> -oj`。
- 云端：OpenAI 兼容 `POST /audio/transcriptions`（Groq `verbose_json`）。
- 语言：`settings.asr.language`（`auto` 时不传）。
- 取消：**per-job AbortController**（不要用全局单例）。
- UI 转写完成必须 `setLiveSegs([])`，否则与 `detail.voice` 合并会翻倍。

